## 1. How do you handle a dynamic web table?

"I never use a fixed row index, because the order changes on reload. I find the row by its key value and read the column I need. 
I wrapped this in a reusable helper, `getDynamicCell(rowName, columnName)`, which reads the header at runtime to find the column index."

```java
By.xpath("//table[@id='taskTable']//tr[td[1][normalize-space()='Chrome']]/td[2]")
```

1. Find the column. It reads all the header cells (Name, CPU, Network, Memory...) and checks which one starts with ‘CPU’. 
	That gives the column number. If no header matches, it throws a clear error instead of returning a wrong value.
	
2. Find the row and read the cell. It uses an XPath that says: ‘pick the row whose first cell says Chrome, 
	then take the cell at the column number from step 1.’
/*
//table[@id='taskTable']//tr[td[1][normalize-space()='" + rowName + "']]/td[" + colNum + "]
//table[@id='taskTable']//tr[td[1][normalize-space()="Chrome"]]/td[4]
* */


Examples: 
public void dynamicWebTableHandling1() {
        driver.get("https://testautomationpractice.blogspot.com/");
        String rowName = "Chrome";
        String colName = "CPU (%)";
        System.out.println("Chome CPU usage is : "+ getDynamicCell( rowName, colName));

    }

    public static String getDynamicCell(String rowName, String columnName) {
        List<WebElement> headers = driver.findElements(
                By.xpath("//table[@id='taskTable']//thead//th"));

        int colNum = -1;
        for (int i = 0; i < headers.size(); i++) {
            if (headers.get(i).getText().trim().startsWith(columnName)) {
                colNum = i + 1;            // XPath is 1-based
                break;
            }
        }
        if (colNum == -1) {
            throw new NoSuchElementException("Column not found: " + columnName);
        }

        return driver.findElement(By.xpath(
                        "//table[@id='taskTable']//tr[td[1][normalize-space()='" + rowName + "']]/td[" + colNum + "]"))
                .getText();
    }

}



## 2. Difference between pom.xml and testng.xml
**pom.xml** It Maven build file, controls the build. helps in manging Dependencies
**testng.xml**TestNG test suite file controls test execution : (Which classes, packages, groups, and methods run; parallel settings; parameters )

pom.xml and testng.xml work together. 
In `pom.xml`, the Surefire plugin points to `testng.xml`, so `mvn test` runs the suite. 
I keep separate suite files such as `smoke.xml` and `regression.xml` and pass the one I want with `-DsuiteXmlFile=smoke.xml`.

| Maven build file 							| TestNG test suite file |

## 3. How is parallel execution achieved in TestNG?

"In `testng.xml`, I set `parallel` and `thread-count`:"

```xml
<suite name="Regression" parallel="classes" thread-count="4">
```

Values are `tests`, `classes`, or `methods`. Data-driven tests can use `@DataProvider(parallel = true)`.

"The important part is thread safety. A static `WebDriver` breaks under parallel runs, so I keep the driver in a `ThreadLocal<WebDriver>` 
inside `DriverManager`. Each thread gets its own browser, and I call `remove()` in `@AfterMethod`. 
For scale I run on Selenium Grid or Docker, and for CI I trigger it from Jenkins."

#Examples: 
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE suite SYSTEM "https://testng.org/testng-1.0.dtd">
<suite name="SauceDemo Regression Suite" verbose="1" parallel="methods" thread-count="3">
    <test name="SauceDemo Checkout Regression">
        <classes>
            <class name="com.selenium.A1_seleniumInterviewEx.selenium26.all.ThreadLocal_Parallel_Example"/>
        </classes>
    </test>
</suite>

public class ThreadLocal_Parallel_Example {

    // 1. Declare the ThreadLocal WebDriver container
    private static final ThreadLocal<WebDriver> driverThreadLocal = new ThreadLocal<>();

    @BeforeMethod
    public void setUp(){

        // 2. Initialize a new ChromeDriver instance for the current thread
        WebDriver driver = new ChromeDriver();
        driver.manage().window().maximize();

        // 3. Store the instance inside the ThreadLocal container
        driverThreadLocal.set(driver);
    }

    // 4. Create a public getter to access the driver instance safely
    public static WebDriver getDriver() {
        return driverThreadLocal.get();
    }

    @AfterMethod
    public void tearDown() {
        // 5. Retrieve the thread-specific driver instance and close it
        if (getDriver() != null) {
            getDriver().quit();
        }
        // 6. Prevent memory leaks by removing the reference from the current thread
        driverThreadLocal.remove();
    }

    @Test
    public void Test_1() {
        // Use getDriver() to launch the application
        getDriver().get("https://www.google.com");
        System.out.println("Thread 1 Title: " + getDriver().getTitle());

    public void Test_2() {
        // Use getDriver() to launch the application
        getDriver().get("https://www.saucedemo.com/");
        System.out.println("Thread 2 Title: " + getDriver().getTitle());
    }

    @Test
    public void Test_3() {
        // Use getDriver() to launch the application
        getDriver().navigate().to("https://www.selenium.dev");
        System.out.println("Thread 3 Title: " + getDriver().getTitle());

## 5. What is an abstract class? Where did you use it?

An abstract class can't be instantiated. It can hold both implemented methods and abstract (unimplemented) methods, and 
child classes must implement the abstract ones.

"In my framework, `BasePage` is abstract. 
It holds common actions such as `click()`, `type()`, waits, and scrolling, and every page class (`LoginPage`, `DashboardPage`) extends it. 
I also have an abstract `TestBase` with `@BeforeMethod` and `@AfterMethod` for browser setup and teardown. 
It avoids duplicate code and keeps behavior consistent."

```java
public abstract class BasePage {
    protected WebDriver driver;
    protected BasePage(WebDriver driver) { this.driver = driver; }
    protected void click(By locator) { 
	/* wait + click */ }
    public abstract boolean isPageLoaded();   // each page defines its own check
}
```


Examples:


public abstract class BasePageAbstract {

        protected final WebDriver driver;
        protected final WebDriverWait wait;

        public BasePageAbstract(WebDriver driver) {
            this.driver = driver;
            this.wait = new WebDriverWait(driver, Duration.ofSeconds(15));
            PageFactory.initElements(driver, this);
        }

        // common action: wait until clickable, then click
        protected void click(By locator) {
            wait.until(ExpectedConditions.elementToBeClickable(locator)).click();
        }

        // your existing helpers stay
        protected WebElement waitUntilVisible(WebElement element) {
            return wait.until(ExpectedConditions.visibilityOf(element));
        }

        protected WebElement waitUntilClickable(WebElement element) {
            return wait.until(ExpectedConditions.elementToBeClickable(element));
        }

        // every page must define its own "am I on the right page?" check
        public abstract boolean isPageLoaded();
    }
	
#Page classes

## 6. WebDriver vs RemoteWebDriver

"`WebDriver` is an interface. 
`RemoteWebDriver` is a class that implements it and sends commands over HTTP to a remote server, such as Selenium Grid, a Docker container, or a cloud provider 
(BrowserStack, Sauce Labs). `ChromeDriver` runs the browser locally. 

In my framework, I switch between them with a config flag, and the test code doesn't change."

## 7. How do you launch the browser dynamically?

"I use a driver factory that reads the browser name from `config.properties` or from a command-line argument, 
so I can run on Chrome, Firefox, or Edge without changing code."

```java
public static WebDriver createDriver(String browser) {
    switch (browser.toLowerCase()) {
        case "firefox": return new FirefoxDriver();
        case "edge":    return new EdgeDriver();
        default:        return new ChromeDriver();
    }
}
```

Run it with `mvn test -Dbrowser=firefox`. 
In `testng.xml` I can also use `<parameter name="browser" value="edge"/>` with `@Parameters("browser")`. 
Selenium Manager (Selenium 4.6+) downloads the right driver automatically, so no WebDriverManager is needed.

## 9. Fetch data from DB with SQL and write it to Excel
**Steps:** 
/**
 * Fetches one employee record from MySQL (classicmodels) and writes it to an Excel file.
 *
 * Step 1: JDBC driver + Apache POI dependencies are in pom.xml
 * Step 2: connect, run query, read the ResultSet
 * Step 3: close the DB connection (try-with-resources)
 * Step 4: write to Excel and close the streams
 */
 
“I add the MySQL connector and Apache POI to the pom. 
I open a connection with DriverManager, run a PreparedStatement with the first and last name as parameters, and 
read the ResultSet into a list, taking the headers from the metadata. 
The connection closes automatically through try-with-resources. 
Then I write the list into an XSSFWorkbook sheet and save it through a FileOutputStream, which is also closed automatically.”


```java
// 1. DB part
String url = "jdbc:mysql://host:3306/dbname";
List<String[]> data = new ArrayList<>();

try (Connection con = DriverManager.getConnection(url, user, pwd);
     Statement st = con.createStatement();
     ResultSet rs = st.executeQuery("SELECT id, name, status FROM employees")) {

    while (rs.next()) {
        data.add(new String[]{ rs.getString("id"), rs.getString("name"), rs.getString("status") });
    }
}   // try-with-resources closes ResultSet, Statement, Connection

// 2. Excel part
try (XSSFWorkbook wb = new XSSFWorkbook()) {
    XSSFSheet sheet = wb.createSheet("DB_Data");
    int r = 0;
    for (String[] row : data) {
        XSSFRow excelRow = sheet.createRow(r++);
        for (int c = 0; c < row.length; c++) {
            excelRow.createCell(c).setCellValue(row[c]);
        }
    }
    try (FileOutputStream fos = new FileOutputStream("output/db_data.xlsx")) {
        wb.write(fos);
    }
}
```
"Credentials come from a properties file or environment variables, never hardcoded. 
I use this for test data setup and for validating UI data against the database."

## 13. Significance of the `.m2` folder

***`.m2`
“.m2/repository is the cache of downloaded dependencies, and settings.xml next to it holds the machine-level configuration: proxy, mirrors, 
repository credentials and the local repository path. 
The pom.xml describes the project, while settings.xml describes the environment, so the same project builds on any machine or network.”



"`.m2` is Maven's local repository, found at `~/.m2/repository`. 
When I build, Maven downloads dependencies (Selenium, TestNG, POI) and plugins from Maven Central once and caches them there in ***.m2 folder ***. 
Later builds reuse the cache, so they are faster and can run offline. It also holds `settings.xml` for proxy, mirror, and repository credentials, 
which matters in a corporate network."

## 14. Can we rename the `.m2` folder? What happens?

"Yes, but Maven then creates a fresh empty `.m2`, so:
- All dependencies and plugins are downloaded again, which is slow and needs internet.
- Offline builds fail.
- `settings.xml` is lost, so proxy, mirror, and credential settings go with it and builds may fail in a corporate network.

If I want a different location, I set `<localRepository>` in `settings.xml` or use `-Dmaven.repo.local=<path>`. If a corrupted dependency is the problem, I delete only that artifact's folder, not the whole `.m2`."

## 15. How do you push code to Git? What is the review process?

1. `git checkout -b feature/login-tests` creates a branch from the updated main.
2. Write the code and run the tests locally.
3. `git status` and `git diff` to review my own changes.
4. `git add .` then `git commit -m "Add login tests"`.
5. **Before pushing:** `git pull --rebase origin main` (or `git fetch` and merge) to get the latest changes and resolve conflicts locally, 
	then run the tests again.
6. `git push origin feature/login-tests`.
7. Raise a **Pull/Merge Request**. A teammate or lead reviews naming, locators, waits, and duplication.
8. The Jenkins pipeline runs the smoke suite on the PR.
9. Fix review comments, push again, and once approved, the code is merged into main.

"I never push directly to main, and I never commit credentials or `target/` (that goes in `.gitignore`)."

## 16. Maven build lifecycle

Maven has three built-in lifecycles: **clean**, **default**, and **site**. The default lifecycle phases, in order:

`validate → compile → test → package → verify → install → deploy`

- **clean** deletes the `target` folder.
- **compile** compiles the source code.
- **test** runs the tests through Surefire, which executes `testng.xml`.
- **package** builds the jar.
- **install** copies the jar into the local `.m2`.
- **deploy** uploads it to a remote repository.

"Running a phase runs all the phases before it. 
In my framework I use `mvn clean test -DsuiteXmlFile=regression.xml` for execution, and `mvn clean package -DskipTests` to build the jar."
